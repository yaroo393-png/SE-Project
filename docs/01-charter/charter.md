## 1. ปัญหา

**ใคร:** ผู้สูงอายุที่ต้องรับประทานยาเป็นประจำ และลูกหลานที่ต้องออกไปทำงาน ไม่ได้อยู่ด้วยตลอดวัน

**เจ็บปวดอะไร:**

1. **ลืมหรือจำไม่ได้ว่ากินแล้ว** — ผู้สูงอายุอาจลืมกินยา กินไม่ตรงเวลา หรือจำไม่ได้ว่ากินแล้วหรือยัง
2. **ผู้ดูแลไม่รู้สถานะ** — ลูกหลานต้องโทรหรือส่ง LINE ถามทุกมื้อ และไม่มีข้อมูลสถานะการกินยารวมไว้ในที่เดียว
3. **ตั้งข้อมูลยายุ่งยาก** — การตั้งข้อมูลยาหลายรายการในแอปมีหลายขั้นตอน **[รอทีมยืนยันว่าเพิ่มข้อนี้]**

**ทำไมวิธีปัจจุบันไม่พอ:**

| วิธีปัจจุบัน | ข้อจำกัด |
|---|---|
| นาฬิกาปลุก | แจ้งเวลา แต่ไม่ทราบว่ากินยาแล้วหรือยัง |
| กล่องยา | ส่งสถานะให้ผู้ดูแลไม่ได้ |
| โทร / ส่ง LINE | ต้องใช้คนตรวจสอบทุกมื้อ |

**สาเหตุหลัก (5 Whys — สมมติฐานเบื้องต้น ต้องตรวจสอบกับผู้ใช้จริง):**

1. ทำไมผู้ดูแลไม่ทราบว่ากินยาแล้วหรือยัง? → ไม่ได้อยู่ด้วยในช่วงเวลากินยา
2. ทำไมไม่อยู่ด้วยแล้วติดตามไม่ได้? → ไม่มีการรายงานสถานะอย่างสม่ำเสมอ
3. ทำไมไม่มีการรายงานสม่ำเสมอ? → ต้องอาศัยการโทรหรือส่งข้อความถาม
4. ทำไมการถามไม่ต่อเนื่อง? → ทั้งสองฝ่ายอาจไม่สะดวกสื่อสารตรงกันทุกครั้ง
5. ทำไมติดตามอัตโนมัติไม่ได้? → ตารางยา การแจ้งเตือน และการรายงานสถานะยังไม่ได้เชื่อมเป็นกระบวนการเดียว

ทั้งโปรเจกต์มีอยู่เพื่อตอบ **2 คำถาม**:

> **คำถามที่ 1 (ผู้สูงอายุ)** — "มื้อนี้ต้องกินยาอะไร และกินแล้วหรือยัง?"\
> **คำถามที่ 2 (ผู้ดูแล)** — "วันนี้กินยาครบทุกมื้อหรือยัง โดยไม่ต้องโทรถาม?"

ฟีเจอร์ไหนไม่โยงกลับไปหาคำถามใดคำถามหนึ่ง ถือว่าอยู่นอกขอบเขต

## 2. ผู้ใช้เป้าหมาย

| ลักษณะ | ผู้สูงอายุ (Senior) | ลูกหลาน / ผู้ดูแล (Caregiver) |
|---|---|---|
| สถานการณ์ | กินยาหลายรายการตามมื้อเป็นประจำ | ทำงานนอกบ้าน ไม่ได้อยู่ด้วยตลอดวัน |
| พฤติกรรมปัจจุบัน | ใช้กล่องแบ่งยา + นาฬิกาปลุก | โทรถามหรือส่ง LINE |
| ความเจ็บปวด | ปิดเสียงเตือนแล้วลืมว่ากินหรือยัง; ไม่สะดวกสมัครบัญชี/กรอกข้อมูล | ติดประชุมแล้วโทรไม่ได้; ต้องเช็กทุกมื้อ |
| ทำอะไรในระบบ | รับแจ้งเตือน ดูรายการยา กดยืนยัน | สแกนฉลาก ตรวจ/บันทึกยา รับแจ้งเตือนเมื่อยังไม่ยืนยัน ดูสถานะรายวัน |
| ต้องการ | ตัวหนังสือใหญ่ ปุ่มใหญ่ กดไม่กี่ครั้ง | แจ้งเฉพาะตอนยังไม่ยืนยัน; ถ่ายรูปฉลากแล้วช่วยกรอกให้ |

**ผู้มีส่วนได้ส่วนเสียอื่น:** ทีมพัฒนา 5 คน · อาจารย์ผู้สอน · เภสัชกร/โรงพยาบาล (ผู้ออกฉลาก — ห้ามระบบตีความหรือเปลี่ยนวิธีใช้ยา) · ผู้ให้บริการภายนอก (Google Gemini สำหรับ spike OCR, GitHub Pages)

## 3. ขอบเขต

### ✅ ทำ (In scope — 5 FR, Must ทั้งหมด)

- **FR-01 จับคู่ Senior–Caregiver** ผ่าน QR / รหัสเชิญ — Senior ไม่ต้องสมัครบัญชี แต่ต้องยินยอมก่อนเชื่อมต่อ → ตอบคำถามที่ 2
- **FR-02 สแกนฉลากยา** → ระบบสร้างร่าง → Caregiver ตรวจ/แก้ก่อนบันทึก (กรอกเองได้ถ้าสแกนไม่ได้) → ตอบคำถามที่ 1
- **FR-03 แจ้งเตือนเมื่อถึงมื้อยา** แสดงยาทั้งมื้อในหน้าเดียว แจ้งซ้ำ 2 ครั้งถ้ายังไม่ยืนยัน → ตอบคำถามที่ 1
- **FR-04 ยืนยันการกินยาทั้งมื้อ** ด้วยการกดครั้งเดียว + บันทึกเวลา → ตอบคำถามที่ 1
- **FR-05 แจ้งเตือน Caregiver** เมื่อยังไม่ยืนยัน + **หน้าสถานะรายวัน** → ตอบคำถามที่ 2
- Prototype เป็น **หน้าเว็บคลิกได้** เปิดในเบราว์เซอร์ ไม่มี backend จริง
- MVP: Caregiver 1 คนต่อ Senior 1 คน **[รอทีมยืนยัน]**

### ❌ ไม่ทำ (Out of scope)

| ไม่ทำ | เหตุผล |
|---|---|
| OCR อ่านลายมือแพทย์ | อ่านไม่แม่น เสี่ยงข้อมูลยาผิด |
| บันทึกผล OCR โดยไม่ผ่านการตรวจสอบ | ความปลอดภัยของข้อมูลยา |
| AI วินิจฉัยโรคหรือแนะนำยา / แนะนำวิธีชดเชยเมื่อลืมยา | ไม่ใช่ผู้ประกอบวิชาชีพ |
| เพิ่ม ลด หรือเปลี่ยนวิธีใช้ยาโดยระบบ | ต้องเป็นตามฉลากเท่านั้น |
| ตรวจสอบว่ากินยาจริง | "กินแล้ว" เป็นการรายงานด้วยตนเอง |
| ยืนยันรายเม็ด / กินไม่ครบทุกรายการในมื้อ | MVP ยืนยันทั้งมื้อ; ใช้ปุ่ม "ยังไม่กิน" แทน |
| ยาเมื่อมีอาการ, ยาน้ำ, ยาครึ่งเม็ด | ไม่มีเวลาแน่นอน / นับเป็นเม็ดไม่ได้ |
| เชื่อมต่อโรงพยาบาล | เกินขอบเขตวิชา |
| Smart Pillbox, IoT, Smartwatch | งบ 0 บาท |
| ค้นหาและจ้างผู้ดูแลมืออาชีพ | ไม่ตอบ 2 คำถามหลัก |
| วิเคราะห์รูปแบบการพลาดยาขั้นสูง | เกินความจำเป็นของ MVP |
| สต็อกยา, แก้ประวัติย้อนหลัง, ผู้ดูแลหลายคน | อาจารย์กำหนด 5 FR → **Future Expansion** |

## 5. กระบวนการพัฒนา (SDLC)

**เลือก: Agile** — ทำเป็นรอบสั้น แต่ละรอบได้ prototype ที่คลิกได้เพิ่มขึ้น แล้วปรับตาม feedback

| รอบ | เป้าหมาย | เสร็จเมื่อ |
|---|---|---|
| 1 | Requirements + Design | SRS (FR, NFR, AC) และ diagram ครบ · Golden Thread โยงทุก FR |
| 2 | หัวใจ MVP | FR-03 + FR-04 คลิกได้ · test กฎการเตือนผ่าน |
| 3 | ฝั่งผู้ดูแล | FR-05 + FR-01 คลิกได้ · test ผ่าน |
| 4 | ข้อมูลยา + ทดสอบ | FR-02 คลิกได้ · test ทั้งหมดผ่าน · ทดลองกับผู้ใช้ (ตัววัดข้อ 6) |
| 5 | ส่งงาน | Final Report · AI-Use Statement · Demo Slides · README |

วันที่ของแต่ละรอบ: **[ใส่ตามกำหนดส่ง M3 / วัน demo]**

**เหตุผลที่เลือก:**

1. **ความไม่แน่นอนสูง** — OCR, การแจ้งเตือน และการใช้งานของผู้สูงอายุยังไม่แน่ใจว่าจะใช้ได้จริง ต้องลองแล้วปรับ
2. **ทำหัวใจก่อน** — รอบ 2 ได้ FR-03 + FR-04 ที่ตอบคำถามที่ 1 ก่อน ถ้าเวลาหมดกลางทางยังมีของที่ใช้ได้
3. **รับ feedback จากผู้ใช้** — ทดลองปุ่มใหญ่/ข้อความเตือนกับผู้สูงอายุจริงก่อนทำต่อ
4. **เหมาะกับทีมประสบการณ์น้อย** — งานแต่ละรอบเล็กพอให้ทดสอบและแก้ทันก่อนรอบถัดไป

### กติกาการทำงานร่วมกัน

- **ติดตามงานผ่าน GitHub Issues** — ทุกงานมี issue และมีผู้รับผิดชอบ 1 คน

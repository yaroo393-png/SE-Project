## 1. ปัญหา

**ใคร:** ผู้สูงอายุในไทยที่มีโรคประจำตัว ต้องรับประทานยาหลายรายการตามเวลาที่กำหนด และใช้สมาร์ทโฟน — กับผู้ดูแล (ลูกหลาน / ผู้ดูแลในบ้าน) ที่ไม่ได้อยู่กับผู้สูงอายุตลอดเวลา

**เจ็บปวดอะไร:**

| # | Pain | หลักฐาน |
|---|---|---|
| PN-1 | ผู้สูงอายุลืม หรือไม่แน่ใจว่ารับประทานยาแล้วหรือยัง | สัมภาษณ์ P1–P4 (§3) |
| PN-2 | ผู้ดูแลไม่รู้สถานะการรับประทานยาแต่ละรอบ ต้องโทรหรือส่งข้อความถามเอง | สัมภาษณ์ P1–P4 (§3) |
| PN-3 | การตั้งข้อมูลยาและเวลาในแอปมีหลายขั้นตอน สำหรับคนที่ไม่ถนัดสมาร์ทโฟน | สัมภาษณ์ P1–P4 (§3) |
| PN-4 | ผู้ดูแลไม่รู้ล่วงหน้าว่ายาจะหมดเมื่อไร | **สมมติฐาน รอยืนยัน** — ยังไม่มีหลักฐานจากผู้ใช้จริง |

**ทำไมสำคัญ:** ผู้สูงอายุพึ่งความจำ นาฬิกาปลุก หรือผู้ดูแล; ผู้ดูแลต้องโทรถามเมื่อไม่แน่ใจ; ประเทศไทยกำลังเข้าสู่สังคมสูงวัย — **[ใส่ลิงก์แหล่งอ้างอิงจริง]**

ระบบนี้มีไว้ตอบคำถามเดียวของทั้งผู้สูงอายุและผู้ดูแล:

> **"ยารอบนี้ กินแล้วหรือยัง?"**

ฟีเจอร์ที่ไม่โยงกลับไปหา PN-1 ถึง PN-4 ถือว่าอยู่นอกขอบเขต

## 4. ขอบเขต

### ✅ ทำ (In scope — MVP)

| FR | ฟีเจอร์ | ตอบ Pain |
|---|---|---|
| FR-1 | วงดูแล: จับคู่เครื่องผู้สูงอายุด้วย QR / รหัส 6 หลัก, เชิญผู้ดูแล, ผู้ดูแลหลัก 1 คน | PN-2 |
| FR-2 | เพิ่มยาจากฉลาก: สแกน → ผู้ใช้ตรวจ/แก้ → บันทึก (กรอกเองได้ถ้าสแกนไม่ได้) | PN-3 |
| FR-3 | เตือนและยืนยันการกินยา: เตือน 3 รอบ, ยืนยัน 1 แตะต่อรอบ | PN-1 |
| FR-4 | แจ้งผู้ดูแลหลักเมื่อยังไม่ยืนยัน | PN-2 |
| FR-5 | สต็อกยา + แจ้งยาใกล้หมด | PN-4 |
| FR-6 | ประวัติการกินยา (ดู + แก้) | PN-2 |

## 8. ข้อสมมติและข้อจำกัด

- **งบประมาณ 0 บาท** — ใช้บริการฟรีทั้งหมด
- Prototype (M3) เป็นหน้าเว็บคลิกได้ ไม่มี backend/ฐานข้อมูลจริง — การแจ้งเตือนและเวลาเป็นการจำลอง
- AI อ่านฉลาก: spike ใช้ Gemini free tier กับรูปที่ลบข้อมูลส่วนตัวแล้วเท่านั้น; prototype ใช้ข้อมูลจำลอง
- ข้อมูลสุขภาพเป็นข้อมูลอ่อนไหวตาม PDPA — เก็บเท่าที่จำเป็น และต้องได้ consent ก่อน
- สมมติว่าผู้สูงอายุใช้ Android และอนุญาตการแจ้งเตือน; ผู้ดูแลมีบัญชี Google
- ฉลากส่วนใหญ่เป็นสติกเกอร์พิมพ์จากร้านยา/โรงพยาบาล — **รอยืนยันด้วยตัวอย่างฉลากเพิ่ม**

## 2. อะไรเวิร์ค

- **หาความไม่ตรงกันระหว่างไฟล์ได้เร็ว** เช่น จำนวนครั้งแจ้งซ้ำ 2 กับ 3, รหัส FR-3 กับ FR-03, ป้าย "(M3 Design)" ทั้งที่ Design อยู่ใน M2, การอ้างหัวข้อผิด (§6 แทน §3.6)
- **ร่างเอกสารตามรูปแบบอาจารย์ได้เร็ว** — SRS 7 ส่วน, AC ทั้งทางถูกและทางผิด, ตาราง INVEST
- **เสนอตัวเลข NFR พร้อมแหล่งอ้างอิง** ทำให้ NFR วัดได้และมีที่มา
- **ชี้กรณีขอบที่ทีมไม่ได้คิด** เช่น มื้อเวลาซ้อนกัน (BR-16), ยืนยันช้าหลัง T+15 (BR-15)

## 3. อะไรไม่เวิร์ค / ต้องแก้เอง

- **ขอบเขต ตัวเลข และกฎการเตือน ทีมตัดสินใจเอง** — AI เสนอทางเลือก แต่ทีมเลือก เช่น Caregiver 1 คน, เสียงเตือนไม่มีรูปยา, เวลาเตือนตามฉลากเท่านั้น
- **AI ลงมือก่อนถาม** — กู้ไฟล์ทันทีโดยไม่ถามว่าข้อมูลที่ขาดคือส่วนไหน ทีมต้องสั่งให้รายงานก่อนแก้
- **AI ลบสิ่งที่ยังใช้อยู่** — ลบประโยค "cap 50%" ที่อยู่ในเทมเพลตอาจารย์, ตัด backlog ทั้งที่ repo ตัวอย่างและคู่มือ M2 ยังใช้ ทีมให้กู้คืน
- **AI ดึงข้อมูลเก่าปน** — ทีมต้องสั่งให้ไม่ใช้ M1/M2 ฉบับเดิม
- **AI แนะนำงานเกินเกณฑ์และอ้างอิงจากความจำ** — แนะนำให้แจ้งเพื่อนเรื่องเปิดเสียงในเบราว์เซอร์ก่อนเปิดดูเกณฑ์ M4 (ซึ่งขอแค่หน้าจอคลิกได้ ไม่ต้องมีเสียงจริง) และอ้างเลข PR ใน Final Report ไม่ครบเพราะไม่ได้เทียบกับ GitHub · ทีมต้องให้ตรวจซ้ำก่อนแก้
- **ค่าที่ต้องมาจากผู้ใช้ AI เดาไม่ได้** — ค่าก่อนใช้ของตัววัดข้อ 6 และวันส่ง M3 ทีมต้องหาเอง

## 4. บทเรียน

1. ให้ `spec.md` เป็นต้นฉบับ ไฟล์อื่นคัดตาม — ตัวเลขเดียวกันต้องตรงกันทุกที่ ไม่งั้นเขียน test ไม่ได้
2. ตรวจกับเอกสารอาจารย์และตัวอย่างทุกครั้งก่อนเพิ่มหรือลบกฎ
3. แยกให้ชัดว่าข้อไหนทีมตัดสิน ข้อไหน AI เสนอ — และบันทึกใน log ทุกครั้ง
4. ตัวเลขต้องบอกได้ว่าวัดเมื่อไร ด้วยอะไร · ห้ามใส่ผลล่วงหน้า

# Product Backlog & MoSCoW Prioritization — MedMind
**Project:** MedMind — ระบบเตือนกินยาและแจ้งสถานะการกินยาให้ผู้ดูแลผู้สูงอายุ  
**Milestone:** M2 Requirements Baseline  

> ไฟล์นี้ใช้ติดตามสถานะงานรายข้อ · ตารางสรุป MoSCoW ที่ส่งอาจารย์อยู่ใน SRS (`spec.md` §3.6) · user story / AC อยู่ที่ `spec.md` §3–§4 · กติกาของระบบ (Business Rules) อยู่ที่ `spec.md` §3.0 · สถานะเป็นของจริง ไม่ใส่ผลล่วงหน้า

## 1. เกณฑ์การจัดลำดับความสำคัญ (MoSCoW Rules)
- **Must Have (MVP):** ขาดไม่ได้ — ถ้าไม่มี ระบบตอบ 2 คำถามหลักไม่ได้ ("มื้อนี้ต้องกินยาอะไร กินแล้วหรือยัง?" / "วันนี้กินครบหรือยัง โดยไม่ต้องโทรถาม?") · อาจารย์กำหนด MVP = 5 FR
- **Should Have:** สำคัญ แต่ตรวจหรือส่งมอบได้หลัง MVP เดินได้ครบ
- **Could Have:** ฟังก์ชันเสริมความสะดวก ทำเมื่อมีเวลาเหลือ
- **Won't Have:** ไม่ทำ เพราะเสี่ยงต่อผู้ใช้ (ข้อมูลยาผิด หรือเป็นคำแนะนำทางการแพทย์)

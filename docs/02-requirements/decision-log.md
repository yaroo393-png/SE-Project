# Decision Log — Requirements (FR-1 ถึง FR-6)

สถานะ: **ร่าง** · ตัวเลขทุกตัว (5 นาที, T+15, 24 ชม., 3–5 วัน, 10 นาที) เป็นเป้าของทีม ต้องยืนยันกับผู้ใช้จริงตอนสัมภาษณ์ / ทดสอบ prototype

## 0. ปัญหา (ฉบับที่ผู้ใช้กำหนด + เติม pain ให้ครบทุก FR)

**ปัญหา:** ผู้สูงอายุที่มีโรคประจำตัวที่ต้องรับประทานยาหลายรายการตามเวลาที่กำหนด อาจลืมหรือไม่แน่ใจว่าได้รับประทานยาแล้วหรือยัง และผู้ดูแลที่ไม่ได้อยู่กับผู้สูงอายุตลอดเวลาไม่สามารถทราบสถานะการรับประทานยาแต่ละรอบได้โดยตรง จึงต้องโทรหรือส่งข้อความเพื่อสอบถามด้วยตนเอง *[เติม]* นอกจากนี้ การตั้งข้อมูลยาและเวลาในแอปมีหลายขั้นตอน และผู้ดูแลไม่รู้ล่วงหน้าว่ายาจะหมดเมื่อไร

**หมายเหตุ:** ประโยคที่ทำเครื่องหมาย *[เติม]* ผมเติมเองเพื่อให้ FR-2 และ FR-5 มีที่อยู่ ต้องให้ทีมยืนยัน; "การตั้งข้อมูลยาหลายขั้นตอน" มีหลักฐานใน M1 แล้ว ส่วน "ยาหมดไม่รู้ล่วงหน้า" **ยังไม่มีหลักฐานผู้ใช้จริง** ต้องสัมภาษณ์

**ใครได้รับผลกระทบ**
- ผู้ใช้หลัก: ผู้สูงอายุในไทยที่มีโรคประจำตัว กินยาตามเวลา และใช้สมาร์ทโฟน
- ผู้ใช้หลัก: ผู้ดูแล (ลูกหลาน / ผู้ดูแลในบ้าน) ที่ไม่ได้อยู่กับผู้สูงอายุตลอดเวลา — ผู้ดูแลหลัก 1 คน + ผู้ดูแลอื่น
- Stakeholder รอง: เภสัชกร / โรงพยาบาล (ผู้ออกฉลาก) — ต้องการให้ข้อมูลฉลากถูกแสดงตามจริง ไม่ถูกตีความใหม่ (มาจาก SRS M2)

**ทำไมสำคัญ:** ผู้ดูแลต้องโทรหรือส่งข้อความถามเมื่อไม่แน่ใจว่ากินยาแล้วหรือยัง (M1); แนวโน้มสังคมสูงวัยของไทย — **[ใส่ลิงก์แหล่งอ้างอิงจริง]**

**ตัววัดความสำเร็จ:** ดูตารางใน `docs/01-charter/charter.md` §5 (ข้อ 1–6 วัดด้วย test, ข้อ 7 วัดกับผู้ใช้จริง ค่าเป้าหมายรอทีมกำหนด)

| Pain | FR | หลักฐาน |
|---|---|---|
| PN-1 ลืมกินยา / ไม่แน่ใจว่ากินแล้ว (ยาหลายรายการ) | FR-3 | M1 สัมภาษณ์ P1–P4; "หลายรายการ" ต้องถามเพิ่ม |
| PN-2 ผู้ดูแลไม่อยู่ด้วย ไม่รู้สถานะแต่ละรอบ ต้องโทร/ส่งข้อความ | FR-1, FR-4, FR-6 (ดู + แก้) | M1 |
| PN-3 *[เติม]* ตั้งข้อมูลยาหลายขั้นตอน | FR-2 | M1 |
| PN-4 *[เติม]* ยาหมดโดยไม่รู้ล่วงหน้า | FR-5 | **สมมติฐาน รอยืนยัน** (ยังไม่มีหลักฐานผู้ใช้จริง) |

**FR-6 ส่วนแก้ประวัติ:** ผูกกับ PN-2 — สถานะที่ผู้ดูแลเห็นต้องถูกต้อง ถ้ากินแล้วแต่ลืมกดแล้วแก้ไม่ได้ ผู้ดูแลจะได้ข้อมูลผิดและยังต้องโทรถามอยู่ดี

**Future Expansion (ไม่อยู่ใน MVP):** นัดหมาย + มอบหมายงาน, Timeline การดูแลทั้งหมด, บันทึกอาการ/ความดัน/น้ำตาล, ค่าใช้จ่าย, AI สรุปอาการ, เชื่อมต่อคลินิก, อุปกรณ์วัดสุขภาพ, ผู้ดูแล 1 คนอยู่หลายวงดูแล

```
T      เตือนรอบ 1   [กินแล้ว] [ยังไม่กิน]
T+5    เตือนรอบ 2   (ถ้ายังไม่ยืนยัน)
T+10   เตือนรอบ 3   (รอบสุดท้าย; กด "ยังไม่กิน" = แจ้งผู้ดูแลหลักทันที)
T+15   ยังไม่ยืนยัน → "ยังไม่กิน" + แจ้งผู้ดูแลหลัก "ยังไม่ยืนยันการกินยา"
```

## 4. Acceptance Criteria (ร่าง)

### FR-2 เพิ่มยาจากฉลาก
1. รูปชัด → สแกน → แสดงร่างครบทุกช่อง ยังไม่บันทึก
2. ผู้ใช้แก้ช่อง → บันทึก → ค่าที่บันทึก = ค่าที่ผู้ใช้แก้ ไม่ใช่ค่า AI
3. ช่องที่อ่านไม่ได้ → ว่าง + "กรุณาตรวจสอบ"; บันทึกไม่ได้จนช่องบังคับครบ
4. ฉลากยาเมื่อมีอาการ → แจ้ง "ระบบยังไม่รองรับยาเมื่อมีอาการ" ไม่สร้างตาราง
5. สแกนล้มเหลว (รูปเบลอ / AI ไม่ตอบ) → เปิดฟอร์มว่างให้กรอกเอง
6. กดยกเลิก → ไม่บันทึกอะไร

### FR-3 เตือนและยืนยัน / FR-4 แจ้งผู้ดูแลหลัก
1. รอบ 08:00 มียา 2 ตัว → 08:00 แสดงเตือน ยาทั้ง 2 ตัวพร้อมจำนวนเม็ด ข้อควรระวัง ข้อห้ามใช้ บนหน้าเดียว
2. กด "กินแล้ว" 08:03 → "กินแล้ว" + 08:03, ไม่มีเตือนซ้ำ, ไม่แจ้งผู้ดูแลหลัก, ตัดยาทุกตัวในรอบ
3. ไม่กด → 08:05 เตือนรอบ 2, 08:10 เตือนรอบ 3
4. ยืนยัน 08:12 → หยุดเตือน, ไม่แจ้งผู้ดูแลหลัก
5. ไม่กดจนถึง 08:15 → "ยังไม่กิน" + แจ้งผู้ดูแลหลัก "ยังไม่ยืนยันการกินยา"
6. กด "ยังไม่กิน" ในรอบ 3 → แจ้งผู้ดูแลหลักทันที ไม่รอ 08:15
7. กด "กินแล้ว" ซ้ำ → ไม่บันทึกซ้ำ ไม่ตัดยาซ้ำ
8. ข้อความถึงผู้ดูแลหลักใช้คำว่า "ยังไม่ยืนยันการกินยา" เสมอ ไม่ใช้ "ไม่ได้กิน"

### FR-5 สต็อกยา + ยาใกล้หมด
1. ยา 10 เม็ด ครั้งละ 2 → ยืนยันครบ 5 ครั้ง → หยุดเตือน + "ยาหมด"
2. ข้ามรอบ (ไม่ยืนยัน) → ไม่ตัดยา
3. วันคงเหลือ ≤ N → แจ้งผู้สูงอายุ + ผู้ดูแลหลัก ครั้งเดียว + ป้ายค้าง
4. เติมยาแล้ว → ป้ายหาย, ถ้าเคย "ยาหมด" กลับมาเตือนต่อ

### FR-6 ประวัติการกินยา (ดู + แก้)
0. สมาชิกทุกคนในวงเห็นรายการรอบยาย้อนหลัง พร้อมสถานะ ("กินแล้ว" + เวลา / "ยังไม่กิน" / "รอยืนยัน")
1. "ยังไม่กิน" → "กินแล้ว" ภายใน 24 ชม. → สถานะเปลี่ยน, ตัดยา, บันทึกผู้แก้/เวลา, แจ้งผู้ดูแลหลัก (ถ้าผู้สูงอายุแก้)
2. "กินแล้ว" → "ยังไม่กิน" → คืนยาเข้าสต็อก, แจ้งผู้ดูแลหลัก (ถ้าผู้สูงอายุแก้)
3. แก้หลัง 24 ชม. → ปุ่มแก้ปิด + "เกินเวลาแก้ไข"
4. สมาชิกที่ไม่ใช่ผู้สูงอายุ/ผู้ดูแลหลัก → ไม่เห็นปุ่มแก้
5. หลังแก้ → ค่าเดิมยังดูได้ในหน้าประวัติ

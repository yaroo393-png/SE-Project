ผู้รับผิดชอบ: Rossatorn Sangkaew / IDK-SleepyBro · Issue [#46](https://github.com/yaroo393-png/SE-Project/issues/46), [#48](https://github.com/yaroo393-png/SE-Project/issues/48)

คู่มือนี้ช่วยซ้อม oral exam หลังอ่านโค้ดจริง ไม่ใช่หลักฐานว่าผู้ใช้ตรวจหรืออธิบายทุกบรรทัดแล้ว งานรอบนี้ใช้ AI ช่วยเขียนและตรวจตาม log ใน `docs/02-requirements/spec.md` §8

## อธิบายงานใน 3–5 นาที

“ส่วนของผมคือหน้าจอและฟีเจอร์จัดการยา FR-02 ผู้ดูแลตั้งเวลามื้อ แล้วกรอกหรือสแกนฉลากเป็นร่าง ตรวจแก้ให้ตรงฉลาก และกดบันทึกเอง ระบบไม่เดาข้อมูลที่ขาดและไม่บันทึกผล OCR อัตโนมัติ ผมแยกตรรกะออกจากหน้าจอเพื่อทดสอบกฎได้โดยไม่ต้องเปิดเบราว์เซอร์ ส่วน OCR และสูตรเวลาเตือนใช้ของเพื่อนผ่านจุดเชื่อมเดิม”

1. เปิด `prototype/role.html` เลือกผู้ดูแล → ยา → เพิ่มยา
2. ครั้งแรกตั้งเวลาเช้า 07:00 กลางวัน 12:00 เย็น 18:00 และเข้านอน 21:00
3. เลือกฉลากตัวอย่างก่อนอาหารเช้า 30 นาที → เห็นเวลา 06:30; เปลี่ยนชื่อหรือจำนวนเม็ดก่อนบันทึก แล้วตรวจว่ารายการใช้ค่าที่แก้
4. ลองก่อนอาหารแต่เว้นนาที → เห็น “กรุณาตรวจสอบ” และบันทึกไม่ได้; ลองยกเลิก → ไม่มียาใหม่
5. ลองก่อนนอน → ไม่ต้องเลือกมื้ออาหารและใช้ 21:00; ลองหลายมื้อ → เห็นเวลาทุกมื้อ
6. อธิบายเทสต์ที่ยืนยันว่าข้อมูลยาอื่นไม่หายเมื่อแก้หรือลบยา

## ข้อมูลเดินอย่างไร

ผู้ใช้กรอกเองหรือระบบสแกนเติมร่าง → `medicine.js` อ่านค่าปัจจุบัน → `validateDraft()` ตรวจช่องบังคับ → `preview()` ขอสูตรจาก `reminder.js` และแสดงเวลา → ผู้ดูแลกดบันทึก → `saveMedication()` ตรวจซ้ำและเขียนผ่าน `store.writeJSON()`

- `validateDraft(draft)` คืน `{ ok, errors }`; ไม่เขียนข้อมูล ตรวจชื่อยา จำนวนเม็ดเต็มบวก และมื้อ/เวลา ก่อนอาหารต้องมีจำนวนนาทีเต็มบวก
- `preview(draft, mealTimes, reminder)` คืนรายการ `{ timing, time, pills }` ของทุกมื้อ โดยใช้ `reminder.reminderTime()` ของทีม: หลังอาหารใช้เวลามื้อ ก่อนอาหารลบนาทีตามฉลาก ก่อนนอนใช้เวลาเข้านอน
- `resolveTimes(medicines, mealTimes, reminder)` คำนวณเวลาแสดงผลจากเวลามื้อล่าสุดโดยไม่เขียนข้อมูลเก่าเอง เช่น เปลี่ยนเช้าจาก 07:00 เป็น 08:00 ยาก่อนอาหาร 30 นาทีจะแสดง 07:30; ยาเก่าที่ไม่มี `timing` คงใช้ `time` เดิม
- `saveMedication(draft, store, reminder, { id, reviewed: true })` ตรวจซ้ำและบันทึกค่าร่างที่แก้แล้ว การไม่มี `reviewed: true` บันทึกไม่ได้ จึงไม่ใช้ผล OCR บันทึกเอง
- `deleteMedication(id, store)` ลบยาตามรหัส ไม่ใช้ชื่อยา เพราะยาคนละรายการอาจชื่อเหมือนกัน
- รายการเก่าที่ไม่มี id ใช้ `legacyIndex` ระบุตำแหน่งที่ตรวจแล้วเพื่อแก้/ลบเฉพาะแถวนั้น กรณีชื่อยาและรายละเอียดซ้ำจึงไม่ลบทั้งหมด
- ยกเลิกคือปิดร่างโดยไม่เรียก `saveMedication()`; การตรวจและ preview ไม่มีผลข้างเคียง จึงไม่เปลี่ยนรายการเดิม

ข้อควรระวังและข้อห้ามใช้ไม่บังคับกรอกถ้าฉลากไม่มี (BR-05) ไม่เพิ่มความถี่ตามวันหรือวันเริ่ม/สิ้นสุด เพราะ requirement ปัจจุบันยังไม่กำหนด

## ทำไมเก็บยาหลายมื้อเป็นหลายแถว

ข้อมูลเดิมที่โครงหน้าอ่านมี `id`, `name`, `dose`, `time`, `instruction` จึงรักษาช่องเหล่านี้ไว้และสร้างหนึ่งแถวต่อมื้อ เพิ่ม `medicationId` เพื่อผูกมื้อของยาตัวเดียวกัน รวมถึง `pills`, `timing`, `caution`, `contraindication` เพื่อเก็บข้อมูลฉลากครบ แก้หรือลบทั้งกลุ่มด้วย `medicationId` โดยไม่แตะยาอื่น และยังรองรับรายการเก่าที่มีแค่ `id`

ชื่อ key ของ localStorage ยังคงอยู่ที่ `store.js` แห่งเดียว ไม่มี server หรือฐานข้อมูลเพิ่ม รูปและข้อความดิบจาก OCR ไม่ถูกเก็บเป็นรายการยา

## ทำไมต้องมี adapter ของสแกน

ระบบสแกนเดิมเติม `name`, `dose`, `time`, `instruction` และเดิมรับมื้อแรกเป็นหลัก หน้าจอใหม่รักษาชื่อเหล่านี้และใช้ adapter ใน `medicine.js` รับ `draft.timings` ทั้งหมด รวมก่อนนอน จำนวนนาทีก่อนอาหาร ข้อควรระวัง/ข้อห้ามใช้ โดยไม่เขียนทับ `scan.js` หรือ `labelForm.js` ของเพื่อน ช่องที่ไม่แน่ใจยังใช้ `needs-review` และผู้ดูแลต้องตรวจเอง

## คำถามที่ควรตอบได้

- ทำไมมีทั้ง `validateDraft()` ใน preview และตอนบันทึก? เพราะข้อมูลอาจถูกแก้หลังแสดงตัวอย่าง ต้องตรวจค่าล่าสุดก่อนเขียน
- ทำไมไม่คำนวณเวลาใน UI เอง? เพื่อใช้สูตร BR-06 แห่งเดียวร่วมกับเพื่อนและตรวจด้วยเทสต์ได้
- ทำไม `logic/` ไม่อ่าน DOM? เพื่อส่งข้อมูลทดสอบเข้าไปได้ตรง ๆ และแยกบั๊กกฎธุรกิจจากปุ่ม/ฟอร์ม
- ทำไมไม่ใช้ชื่อยาเป็น id? ชื่อซ้ำได้ แต่รายการและมื้อต้องแก้/ลบได้ถูกตัว
- ทำไมบันทึกได้หลังตรวจเท่านั้น? ผล OCR อาจอ่านผิด BR-04 และ NFR-06 จึงกำหนดให้ผู้ดูแลตรวจและกดยืนยันเอง
- งานใดเป็นของเพื่อน? OCR, parser, store และสูตร reminder; งานรอบนี้ต่อผ่าน API เดิมและแยกไฟล์ตาม #46 ไม่อ้างว่าเป็นคนเขียน logic เหล่านั้น
